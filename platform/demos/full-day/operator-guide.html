Prepare and prove the environment

Restore and validate
before the room.

  • Use approved feeds.
  • Validate source and generated workflows.
  • Capture only after content is final.

Use Node.js 22 or newer. Inspect the effective registry and preserve the lockfile. On a Microsoft-managed machine with no approved project-specific registry, restore through the approved feed:

npm config get registry
npm ci --ignore-scripts --no-audit --no-fund --registry=https://packagefeedproxy.microsoft.io/npm/
npm test
npm run validate
npm run validate:html
npm run validate:workflows
npm run capture

Do not switch to a public registry when a locked version is unavailable. Resolve the approved-feed or quarantine issue before rehearsal.

The source repository is
the prepared product.

  • Fork baseline equals demo baseline.
  • Complex controls are preconfigured.
  • Recovery artifacts are revisioned.

  • Service baseline and all deterministic tests pass.
  • Synthetic dual-case intake, feature and bug Issue forms, agents, project skills, PR template, CI, release rehearsal, review workflows, and recurring Agentic Workflow source and lock are on the default branch.
  • Forking, Issues, Actions, Codespaces or local clone, and local Copilot are enabled. Cloud-agent assignment and Copilot code review each pass their separate enterprise or organization policy check.
  • The Station organization has at least one assigned Copilot seat. Copilot CLI and Allow use of Copilot CLI billed to the organization are enabled at the policy level that enforces the setting. This is the organization-billed path for Agentic Workflows; an enterprise Copilot purchase or an enabled CLI client does not replace this separate billing policy.
  • Station organization access enables Code Quality for all current and future workshop repositories; the live preflight verifies each repository reports configured.
  • The instructor has prepared feature and bug Issues, two Goal Cards, local and cloud PRs, check runs, review comments, release evidence, and Agentic Workflow outcomes.
  • Every recorded or simulated state is labeled before presentation.

Automate what the APIs can prove

  1. Assign the delivery account a Copilot seat in the Station organization. Verify GET /orgs/ORG/copilot/billing reports at least one seat and GET /orgs/ORG/copilot/billing/seats names the intended account.
  2. Enable Code Quality for every Station repository through PATCH /repos/OWNER/REPO/code-quality/setup, then wait for its initial analysis and a PR-bound Code Quality: PR #NUMBER run.
  3. Compile the checked-in Agentic Workflows and preserve their lock files. The workshop sources use gpt-5.3-codex, which the target-host rehearsal returned in its live Copilot model catalog.
  4. Run the live preflight against one prepared repository. A CLI version, seat, or compiled workflow is necessary evidence, but none independently proves inference.

Complete the enterprise controls manually

  1. In Enterprise AI controls, enable Copilot CLI, Copilot code review, AI credits paid usage, and Allow use of Copilot CLI billed to the organization. If the enterprise delegates a policy, enable it in the Station organization instead.
  2. Open the Station organization policy page. Confirm inherited controls are visibly ON; a grey control that is OFF is an enterprise denial, not a successful organization configuration.
  3. Create a disposable PR after the policies and seat are active. Require green deterministic CI, a successful Code Quality PR run, successful Goal Review and Documentation Review runs, and both revision-bound workflow comments.
  4. Request native Copilot code review from the PR sidebar. Do not treat an HTTP 201 from the review-request API as proof: verify an actual Copilot review or review event on the current head. Record a missing review as a capability failure and use the facilitator fallback.

Rehearse as an attendee.
Record the exact boundary.

  • Start from a clean fork.
  • Use the delivery account and host.
  • Record capability gaps, not guesses.

  1. Authenticate the designated instructor account on the target GitHub host. Remove environment tokens that shadow the approved keyring login.
  2. Create a uniquely named disposable rehearsal fork or repository. Never reuse a participant repository.
  3. Run Labs 1-5 in order from the attendee guide. Record repository URL, default branch, account, start SHA, each check conclusion, preview capability, fallback used, and final SHA.
  4. Repeat the opening walkthrough from its prepared states and time every transition.
  5. Clean up only the exact rehearsal resources after ownership and workshop marker verification.
$env:GH_HOST = "YOUR-GITHUB-HOST"
$owner = gh api user --hostname $env:GH_HOST --jq .login

Resolve the owner from the authenticated session; do not commit the host, account, token, or repository name into a profile.

Stop: do not call a lab live-ready if the required participant action was replaced by an unlabeled recording, the recovery artifact does not match the current source, or a cleanup target is ambiguous.

Prepare the tools.
Students deploy the template.

  • Allocator owns one resource group per station.
  • Test/prod use tags and distinct federations.
  • Image security takes priority over ACA.

The existing lab allocator creates one resource group per station. Do not change that allocator or create a second group for prod. Provide its exact subscription/group ID and original allocation ownership tag to the student. Environment=test|prod labels resources inside the same group.

  1. Prepare Azure CLI and sign-in in the actual student Codespace or laptop before Lab 4. Confirm group-scoped resource creation and role-assignment rights, registered ContainerRegistry, KeyVault and ManagedIdentity providers, quota for two Basic registries per station, and globally unique generated names. Register App only for optional ACA.
  2. Approve a current docker.io/library/node:24-alpine@sha256:... base reference and provide it to students. Resolve it with docker buildx imagetools inspect docker.io/library/node:24-alpine on the instructor machine; the workflow deliberately refuses a mutable tag.
  3. Set a small event budget and the group retention policy. ARM creates two Basic ACRs, two standard vaults, two managed identities, and explicit roles. No new database, storage state backend, Terraform provider install, or group creation is needed.
  4. Explain the requested Owner-on-one-group shortcut. Both pipeline identities can change authorization for all resources in the group. Tags, separate registries and client IDs are not least-privilege isolation. Use no sensitive data or real production resources in this group.
  5. Verify the issuer on the target host. GitHub.com uses https://token.actions.githubusercontent.com; GHE.com uses https://token.actions.SUBDOMAIN.ghe.com or its explicitly configured enterprise issuer. Never guess a GitHub.com issuer for GHE.com.
  6. Rehearse plan, what-if, deploy --apply, wire --apply, and preflight with platform/scripts/oci-platform.mjs. Configuration lives in ignored .workshop/azure-release.json, populated from the trusted allocation, not from an inferred group name.
  7. After students inspect the two subjects, wire immutable environment-bound federation. workshop-test selects main; workshop-prod selects main, requires the verified reviewer, prevents self-review, and disables administrator bypass. Compatible existing policies stay intact; incompatible policies block setup.
  8. Record the actual successful OCI workflow: tests, container smoke, test signature, identical prod digest, prod signature, and approval record. A dry-run plan or preflight is not live release evidence. Prepare one completed instructor run and one signed baseline for recovery; preserve their original SHA and repository.

Allow 15 minutes for reviewed agent-led resource deployment, 8 for identity mapping, 10 for the test image path, 9 for prod approval, and 8 for verification/decision. If registration, RBAC propagation, or deployment exceeds the cap, use the instructor station with an explicit label. Do not spend the image/security time debugging optional ACA.

For optional ACA, choose deployAca=true only when time and budget permit, re-review the what-if, and wire the optional outputs. The runtime has a separate AcrPull-only identity; never attach an Owner pipeline identity to a container. Use the provided template, the verified digest, one ephemeral replica, and same-origin API/frontend. Stock resets on restart. Mention Azure SRE only when available; there is no SRE lab setup.

Prepare any optional security demonstration separately on the current target host. This repository does not ship historical demo fixtures or recorded security evidence.

Run the progressive labs

Lab 1 creates
two bounded needs.

  • Fork before writing.
  • Separate feature from bug.
  • Approve each write.

Verify each attendee works in their own fork and can open a Codespace or approved local clone. Lab 1 ends with one feature Issue and one bug Issue. The refiner may not combine them or use one approval for both writes.

Recovery at minute 35: use the two reference Issue artifacts while preserving the attendee's evidence classification and approval decisions.

Lab 2 compares
local and cloud loops.

  • Publish context before delegation.
  • Observe red before green.
  • Receive two PR handoffs.

Require both approved Goal Cards to be present in Issue comments before assigning the bug. Stop the local path after the red test and before commit. Monitor the asynchronous bug PR without making the room wait for model execution.

Recovery at minute 45: use the feature reference test or implementation and the instructor's source-bound cloud PR. Label a delayed or unavailable assignment rather than impersonating it.

Lab 3 challenges
both handoffs.

  • Two PRs, two revision identities.
  • Deterministic and reasoning evidence differ.
  • Humans decide each merge.

Use the feature PR for the full review path and compare the cloud PR handoff. Request native review on current heads. Code Quality and organization-billed Agentic Workflow execution are live only when preflight marks each one PASS; attendees inspect findings but do not change billing or organization policy. Merge the feature only when its required evidence is complete.

Recovery at minute 30: use the instructor PRs to compare scopes, then record any missing station capability rather than fabricate a pass.

Lab 4 promotes
one secured image.

  • Students deploy a reviewed template.
  • Test/prod use distinct identities and signers.
  • Approval promotes the same digest.

Provide the allocator output and use /azure-release to review/deploy the prepared template. Students confirm the two federations and environment-variable mappings; pair prod dispatchers with different reviewers. The workflow builds once, signs and verifies in test, then copies the exact manifest to prod for its separate signature.

Recovery at minute 15: move stalled infrastructure setup to the prepared instructor station. At minute 35, prioritize digest and signature verification over ACA. Missing own-station authority or rollback still produces BLOCKED; do not transfer an instructor run's pass to the attendee fork.

Lab 5 authors
two bounded agentic steps.

  • Triage comments once.
  • Readiness advises only.
  • Pulse reconciles owned state.

Participants author triage, complete the readiness scaffold, and compile both only with the approved toolchain. They then inspect repository pulse for ownership and no-op reconciliation. Live execution remains capability-gated.

Recovery at minute 25: use the readiness reference and review both sources without claiming execution. Keep SRE agent comparison optional and capability-gated.

Profiles, adoption, and migration

Configuration changes.
The learning model does not.

  • Sandbox labels missing enforcement.
  • Station demonstrates central policy.
  • Neither changes the core artifact chain.

Before Lab 1, announce the selected profile and a short capability matrix for forking, Codespaces, local Copilot, cloud-agent assignment, Copilot code review, Agent Skills, Actions, Code Quality, environment review, rulesets, Agentic Workflow compilation, and organization-billed Agentic Workflow execution. Present CodeQL, secret scanning, push protection, and Autofix as a separate verified facilitator demo.

From 15:00 to 15:30, move from the completed loop to adoption and Azure DevOps migration. Map intent, code, evidence, authority, identity, and release boundaries before discussing individual product features. Extended deliveries add one hour for repository and pipeline inventory, coexistence, Actions Importer output, OIDC, and migration waves.

Reset, cleanup, and evidence retention

Dry-run cleanup.
Delete only proven workshop resources.

  • Resolve exact targets.
  • Verify ownership markers.
  • Retain the rehearsal record.

  1. Export the rehearsal record and links required for presenter evidence.
  2. List the exact disposable rehearsal repository and branch names. Verify ownership and the event's recorded allocation; a participant fork is not a disposable generated station.
  3. Review the exact proposed deletions with the repository owner. There is no repository-generating or repository-deleting workshop script.
  4. After explicit approval, remove only the confirmed rehearsal resources through GitHub. Never use wildcard or broad organization deletion.
  5. Re-run preflight before the next delivery rather than trusting retained state.

Do not delete participant repositories unless the event's explicit retention policy and owner approval require it.

Azure cleanup remains with the existing allocator. Retain image digests, signing verification and approvals before the allocated group is removed. The OCI helper intentionally has no group creation/deletion command; purge-protected Key Vaults remain soft-deleted for their seven-day retention period.

The workshop is ready only when a clean-start attendee path and the exact presenter path both work, every unavailable control is labeled, and every fallback preserves the original trust boundary.
