# Documentation review

Review the pull request diff and documentation that describes the changed
behavior. Do not edit files.

Report only documentation that becomes false, incomplete for the documented
user journey, or misleading about live versus simulated behavior. Cite the
changed code and exact documentation path. If no documentation change is
required, explain why in one sentence. Do not request prose churn, duplicate
code comments, or new documents unrelated to the change. Bind the review to the
exact revision inspected.
