Separate intent from authority

One platform.
Three loop shapes.

  • Issue events need classification.
  • Release evidence needs advice.
  • Schedules need reconciliation.

An Agentic Workflow is justified when a repeatable trigger needs contextual evidence and a bounded recommendation. It is not justified merely because an agent can perform the task.

Issue triage
An Issue-opened event reads untrusted intake and may publish one advisory comment.
Deployment readiness
A manual run reads immutable release evidence and reports readiness without approving an environment.
Repository pulse
A schedule reconciles seven days of repository state into one owned, updateable Issue.

Checkpoint: for each pattern, name the trigger, evidence, worst permitted effect, stop condition, and remaining human decision.

Public preview

GitHub Agentic Workflows are public preview. Source changes are proposals until an approved compiler regenerates the lock, the source and lock diff are reviewed together, and the repository accepts the workflow.

Write the source contract

The prompt proposes.
Frontmatter constrains.

  • Trigger only on opened Issues.
  • Read only needed evidence.
  • Publish one bounded comment.

  1. Create a branch named lab-05-issue-triage.
  2. Copy the control skeleton to .github/workflows/issue-triage.md.
  3. Complete the instruction body so the comment reports one type: FEATURE, BUG, QUESTION, or NEEDS CLARIFICATION; cites its evidence; and names the next human decision.
  4. Keep issues: read, one add-comment safe output, threat detection, the five-minute timeout, and the 30-credit cap. Do not add general write permissions or network access.

Expected result: a reviewer can tell what starts the workflow, what it may read, its worst permitted effect, when it stops, and who still owns the decision.

Reason over evidence.
Never replace the gate.

  • Read exact revision evidence.
  • Report READY or BLOCKED.
  • Leave approval to the environment.

  1. Copy the prepared scaffold to .github/workflows/deployment-readiness.md.
  2. Complete its three instruction fields: required evidence, conditions that force BLOCKED, and the human decision that remains.
  3. Require the run ID and attempt, candidate SHA, test/prod ACR repositories with the same OCI digest, both strict Notation verifications and pinned signers, prod approval, identity mapping, rollback digest, deterministic and smoke results, unresolved findings, and merged PR to agree. Explicitly label the lab's same-group Owner-role shortcut rather than calling it production isolation.
  4. Keep the workflow read-only with noop as its only safe output. It reads GitHub evidence only; it must not query Azure, sign an image, approve an environment, execute artifacts, access secrets, or deploy.

Expected result: reasoning can summarize operational evidence, but only the deterministic workflow and GitHub Environment can establish or exercise their controls.

If you run out of time, compare your source with the reference contract.

Turn reviewed source into observable operation

Source and lock
must travel together.

  • Compile with an approved toolchain.
  • Review generated authority.
  • Keep stale locks unmerged.

  1. Commit the source and open a draft PR.
  2. If the approved gh aw compiler is available, run: 
    gh aw compile --dir .github/workflows --validate
  3. Commit both generated lock files to the same PR. Review that triage has one comment output while deployment readiness remains read-only and can only return a no-op report.

If compilation is unavailable, keep the PR draft and review the source contract against the reference. That is a source review, not proof of an executable workflow.

Inspect a recurring reconciliation loop

Recurrence requires
ownership and no-op.

  • Reconcile before publishing.
  • Update one owned artifact.
  • No change means no write.

Open .github/workflows/repository-pulse.md and compare it with your two event-specific workflows.

Owned state
The marker identifies the one Issue this workflow may create or update.
Reconciliation
Closed, waiting-human, duplicate, or unchanged state produces no write rather than another report.
Budget
Timeout, inference credits, one create, and one update bound each run.
Authority
The workflow recommends no more than three actions; owners still prioritize and execute them.

Optional extension: if the environment exposes an SRE agent, compare its evidence, tool access, and authority boundary with deployment readiness. Do not represent unavailable or recorded behavior as live.
