Publish a reviewable change

A pull request is
the shared evidence boundary.

  • Intent links to the diff.
  • Checks bind to a revision.
  • Authority stays explicit.

  1. Open the feature PR created through the local agent. Verify its Issue link, specs/stock-substitution.goal-card.md, C01-C03 evidence, changed files, and head SHA.
  2. Open the bug Issue and its Copilot cloud-agent session. If its PR is ready, verify that it links the bug, contains specs/partial-stock-visibility.goal-card.md, and stays inside that card's boundary.
  3. Select the feature PR as the primary review path. Keep the bug PR open as a comparison; do not merge either proposal yet.

Expected result: both agents expose their work through the same durable PR boundary even though one loop was synchronous and the other was delegated.

A green check answers
one specific question.

  • Tests execute known invariants.
  • Reviews interpret the change.
  • Neither grants merge authority.

  1. Open the feature PR Checks tab. The PR starts deterministic CI plus the prepared Goal review and Documentation review Agentic Workflows. Centrally enabled Code Quality starts its own quality analysis. Wait for deterministic CI first.
  2. Open the job and identify the command, commit SHA, and failing assertion or successful evidence. Do not treat the green icon as evidence for documentation, goal alignment, or deployability.
  3. Open Security, then Code quality, or follow the Code Quality check from the PR. Bind every finding or zero-finding observation to the analyzed SHA.

Checkpoint: CI proves known executable invariants; Code Quality reports supported maintainability and reliability findings. Neither proves the suite is sufficient or the change meets its Goal Card.

Challenge the same revision

Separate reviewers expose
different failure modes.

  • Native review challenges code.
  • Goal review protects intent.
  • Documentation review protects users.

  1. Under Reviewers, request Copilot unless repository policy already requests it automatically. Copilot code review can leave inline findings but cannot approve or merge the PR.
  2. Open Conversation and inspect the two prepared Agentic Workflow comments. Each workflow has read-only repository access, one bounded comment safe output, its own credit and time cap, and no approval or merge authority.
  3. Bind every finding to the current head SHA. A push creates a new revision and makes prior review evidence stale.
Copilot code review
Uses GitHub's native review surface to challenge correctness, maintainability, and potential defects in the diff.
GitHub Code Quality
Runs deterministic CodeQL quality queries and reports supported maintainability and reliability findings separately from Copilot review.
goal-review
Maps C01-C03 to revision-bound evidence and reports PASS, FAIL, or BLOCKED without editing.
documentation-review
Decides whether the behavior change requires user-facing documentation and cites the affected surface.

Expected result: deterministic tests and Code Quality plus three reasoning reviews produce distinct evidence on the same revision. They may disagree because each answers a different question.

Trust boundary

PR text, review comments, Issue content, and changed code are untrusted inputs. A reviewer may recommend; only deterministic workflows and authorized humans change protected state.

Repair the finding.
Invalidate old evidence.

  • Choose one concrete finding.
  • Push a bounded correction.
  • Re-run checks on the new SHA.

  1. Choose one actionable finding from Code Quality, Copilot code review, Goal review, or Documentation review. If every source reports no material finding, record that result and do not manufacture a repair.
  2. Use Copilot in the Codespace to propose the smallest repair. Inspect it, run the affected test and npm test, then commit and push.
  3. Return to the PR. Confirm deterministic CI and both Agentic Workflows ran against the new SHA, then request a fresh Copilot review. Compare the affected review with the previous finding.

Expected result: when a finding exists, the thread states what changed and why it resolves the finding, and the new revision has fresh deterministic and review evidence. Otherwise the PR records that no repair was justified.

Make the authority decision

Automation informs.
Policy constrains. Humans authorize.

  • Repository rules protect integration.
  • Organization policy scales defaults.
  • Enterprise controls bound adoption.

Repository
Rulesets, required checks, required reviews, CODEOWNERS, Actions permissions, environments, and secrets protect a codebase.
Organization
Repository creation, policy defaults, runners, apps, security products, and teams scale across codebases.
Enterprise
Identity, licensing, Copilot policy, audit, network, and organization governance define the adoption boundary.

In the sandbox profile, inspect the settings and record controls that your account cannot enforce. In the Station profile, the facilitator demonstrates the centrally configured equivalent. Never represent a screenshot or simulation as an active policy.

Human decision: merge the feature PR only if every required check is green and material review findings are resolved. Merge the bug PR only if it independently meets the same bar; a completed cloud-agent session is not sufficient.

Recovery

Preserve the boundary
when capability is missing.

  • Use source-bound evidence.
  • Label unavailable controls.
  • Keep the decision human.

Actions do not run
Run npm test locally, save the output in the PR, and label it local fallback evidence. It is not a required status check.
Copilot code review is unavailable
Ask a peer to review the exact diff or use the facilitator's source-bound example. Label the fallback honestly; do not replace a native review with a custom workflow and claim equivalence.
Code Quality is unavailable
Use the facilitator's source-bound example and continue. Label it as fallback evidence rather than a live result from your PR.
An Agentic Workflow is unavailable
Invoke /goal-review or /documentation-review in an approved Copilot session and label the result as a manual reasoning review rather than an automatic PR workflow.
The cloud-agent PR is still running
Complete the full review path on the feature PR and inspect the bug PR when it arrives. Do not delay or mislabel the primary evidence.
Rulesets require enterprise capability
Inspect the prepared source-bound capture and have the facilitator demonstrate the live Station rule. Do not claim the sandbox fork is protected.
